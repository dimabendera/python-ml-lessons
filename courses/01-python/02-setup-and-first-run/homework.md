# Домашнє завдання · Встановлення й перший запуск

> Лекція: [lecture.html](lecture.html) · Практика: [practice.ipynb](practice.ipynb) · Тест: [quiz.html](quiz.html)

Усе, що тут є, робиться **у власному терміналі**, а не в зошиті. Зошит показував механіку —
а вміти треба руками.

---

## 🟢 Рівень 1 — База

Зроби своїми руками весь шлях із лекції: постав Python, знайди термінал, створи файл,
запусти його.

1. Перевір версію: `python3 --version` (на Windows — `python --version`).
2. Створи теку `projects` у домашній теці.
3. Створи в ній файл `pryvit.py`, який друкує твоє ім'я й сьогоднішню дату **однією**
   командою `print`. Дату вписуй текстом — модулів ми ще не проходили.
4. Перейди в теку командою `cd`, переконайся командою `ls` (Windows: `dir`), що файл там,
   і запусти його.
5. Тепер вийди на рівень вище (`cd ..`) і запусти той самий файл **звідти**, не заходячи
   в теку назад.

**Зроблено, якщо:** ти можеш показати два різні рядки команд, які запускають один і той самий
файл із двох різних тек, і пояснити, чим відрізняються шляхи в них. І якщо `python3 --version`
друкує 3.12 або новішу.

## 🟡 Рівень 2 — Плюс

Тепер навмисно зламай і полагодь.

1. Візьми свій `pryvit.py` і зроби в ньому **чотири** окремі поломки — по одній за раз,
   щоразу повертаючи файл до робочого стану:
   `NameError`, `SyntaxError`, `IndentationError`, `TypeError`.
2. Для кожної збережи повний текст traceback у файл `pomylky.txt` (просто скопіюй із
   термінала) і допиши під ним три рядки:
   - який рядок файлу винен (номер);
   - який фрагмент підкреслили стрілки;
   - що саме треба виправити.
3. Окремо перевір твердження з лекції: постав `SyntaxError` в **останній** рядок файлу й
   переконайся, що перший `print` теж не спрацював.

**Зроблено, якщо:** у `pomylky.txt` чотири traceback і дванадцять рядків розбору, а на
питання «чому при синтаксичній помилці не друкується навіть перший рядок» ти відповідаєш
без підказки.

## 🔴 Рівень 3 — Виклик

Розберись, який саме Python у тебе працює і звідки він береться.

1. Дізнайся повний шлях до свого інтерпретатора:
   `which python3` (macOS/Linux) або `where python` (Windows).
2. Подивись увесь список PATH: `echo $PATH` (macOS/Linux) або `$env:Path` (PowerShell).
   Розбий його на окремі теки — це список, розділений двокрапкою (`:`) або крапкою з
   комою (`;`).
3. Знайди в цьому списку **всі** теки, у яких лежить хоч якийсь `python`. Для кожної
   з'ясуй версію: `/повний/шлях/до/python3 --version`.
4. Побудуй маленьку таблицю: тека → версія → звідки вона там узялася (система, інсталятор
   з python.org, Homebrew, менеджер пакетів).
5. Дай відповідь: чому запускається саме той інтерпретатор, який запускається?

**Зроблено, якщо:** таблиця складена, і ти можеш **передбачити наперед**, яка версія
відповість на `python3 --version`, дивлячись лише на порядок тек у PATH — а потім перевірити
й отримати збіг.

## Підказки

- Якщо `python` на Windows відкриває Microsoft Store — це не Python, а системна заглушка.
  Шукай галочку «Add python.exe to PATH» у повторному запуску інсталятора (кнопка Modify).
- Traceback краще копіювати **весь**, а читати починати **з кінця**. Останній рядок — діагноз,
  усе вище — маршрут до нього.
- У завданні 3 не намагайся редагувати PATH, поки не побудував таблицю. Спершу зрозумій,
  що там уже є, — половина «проблем із PATH» розсмоктується на цьому кроці.
- Якщо в списку PATH знайшлася тека, якої не існує, — це нормально. Оболонка мовчки її
  пропускає.
