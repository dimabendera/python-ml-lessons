рівень 1Рівень 1 — База

Напиши файл kalkulyator.py з функцією podilyty(a, b), яка повертає a / b.

  1. Обгорни ділення в try / except із конкретним типом: при діленні на нуль функція має повертати рядок "на нуль ділити не можна", а не падати.
  2. Додай другу гілку except TypeError, яка повертає "аргументи мають бути числами" — вона спрацює, якщо передати рядок.
  3. Додай блок finally, який дописує +1 до глобального лічильника викликів.
  4. У кінці файлу, під if __name__ == "__main__":, постав перевірки:

python assert podilyty(10, 2) == 5.0 assert podilyty(10, 0) == "на нуль ділити не можна" assert podilyty("десять", 2) == "аргументи мають бути числами" assert викликів == 3, "finally мав спрацювати на кожен виклик" print("✅ рівень 1")

Зроблено, якщо: python3 kalkulyator.py друкує ✅ рівень 1 і більше нічого; у файлі немає жодного голого except: і жодного except Exception.

Підказки

  • Не вгадуй тип винятку — спитай. Обгорни підозрілий рядок у try: ... except BaseException as e: print(type(e).__name__, e). Це разова діагностика, а не код, який лишається: дізнався тип — заміни на конкретний.
  • float("28.5") і float(None) падають по-різному. Перший дає ValueError (рядок є, але не схожий на число), другий — TypeError (рядка немає взагалі). У завданні другого рівня це пригодиться.
  • Щоб finally було видно, друкуй у ньому рядок або дописуй у список. Інакше легко переконати себе, що він виконався, не перевіривши цього.
  • Власний виняток успадковуй від Exception, не від BaseException. Інакше твоя біда поведеться як Ctrl+C і проскочить повз усі чужі обробники.
  • Якщо assert мовчить — це успіх. Він друкує щось лише тоді, коли все погано. Тому наприкінці ставлять print("✅ …"): інакше не видно, що перевірка взагалі була.
  • Файли __pycache__ у роботу не здаються.
